# 游戏体检与安全恢复

这次开发参考了用户提供的「Bilibili@热心网友033 V6.0.2 一键 DLSS5」压缩包，保留 DLSS 5 MANAGER 原有 F# / Avalonia 界面和安装路线，重新实现适合本项目的检查和文件恢复功能。

## 思路与实现对应

| 参考包中的思路 | 本项目中的实现 |
| --- | --- |
| `pe_inspection.ps1`：按可执行文件识别平台和图形接口 | `PeInspection.fs` 静态读取 PE 头、普通导入表和延迟导入表，区分 x86、x64、ARM64；不加载或运行游戏 |
| `game_rules.json`：逐游戏规则 | 管理页可导入完整规则表；精确匹配 exe 文件名，显示 API、挂载名、反作弊提醒和原备注；导入数据不会执行脚本 |
| `checkup.ps1`：从运行日志判断状态 | `HealthCheck.fs` 检查 ReShade、OptiScaler、Feeder、033 核心及补帧日志；每份最多读取尾部 1 MiB，标注日志更新时间 |
| `deployment_transaction.ps1`：按内容保护备份和恢复 | `DeploymentSafety.fs` 保存原文件与部署文件的 SHA-256、原文件属性和时间；先检查全部恢复项，再恢复文件 |
| 失败后撤销本次操作 | 为本次操作保留独立快照，失败修复回到“修复前”的状态；首次安装时的原始备份继续保留 |

参考包的整张游戏表、安装脚本、DLL、模型及着色器没有被复制进仓库。用户可以从自己解压的包导入规则。保留原项目 NODIX TECH / Numidia Studios 署名；参考思路来自 B站 @热心网友033 整理的上述包。

## 使用方法

1. 在游戏卡片打开 Manage（管理），确认目标是真正的游戏 exe。
2. 可点击「导入游戏规则」，选择解压包中的 `managed/game_rules.json`。导入器接受 `Schema: 1`、`Kind: "033-game-rules"` 格式，限制文件大小和字段长度，拒绝重复或带路径的 exe 名称。提供的包包含 303 条规则，已用完整原表验证解析。
3. 点击「游戏体检」查看架构、图形导入、已有代理 DLL、反作弊标记、备份问题与日志观察。
4. 点击「导出报告」，选择本地 TXT 文件保存。报告含本地路径，导出不会上传到社区或其他服务。
5. 正常安装、修复或卸载均走新的文件保护逻辑。切换路线先检查新路线所需的基本文件，避免在明显缺少安装包时先卸掉旧路线。

导入规则的 API 只在可执行文件没有明确图形导入时作为补充。多个图形 API 导入仍显示不确定，不自动认定最高版本就是当前渲染模式。规则内的特殊安装目录、RE 引擎适配路线及 `Mount` 不会直接改写部署目标；挂载名只用于体检建议。本项目的 payload 与 033 包不同，因此不能把参考包的兼容性说明当作本项目的实测结论。

## 恢复行为

- 新安装记录保存在 `%LOCALAPPDATA%\DLSS5Manager\Installs`，原始备份保存在 `Backups`。
- 覆盖前验证备份；部署先复制到同目录临时文件、验证哈希，再替换目标。
- 卸载前验证所有备份、目标范围与文件所有权，拒绝目录冒充文件及符号链接/重解析点路径。
- 原文件恢复后保留原写入时间和文件属性。第一次安装的备份不会被后续修复重新定义。
- 游戏更新或其他工具改动了受管 DLL 时停止恢复；保留恢复记录和备份，供排查和重试。
- 已更改的 `.ini`、`.cfg`、`.log` 保留在原位置，不覆盖玩家设置；原始备份继续保留。
- 不再按“看起来像某种模组”的名称清扫其他文件。没有恢复记录的外部安装，应使用原安装器卸载。
- 恢复中途失败不会删除恢复记录。已经恢复的项支持再次执行，失败的项可以在消除原因后继续。
- 单次安装失败时尽量还原本次操作前的文件；若恢复被外部修改或 IO 错误阻断，明确报告失败并在 `Backups/<game>/attempts/<id>/recovery.json` 保留快照清单。
- 同一恢复记录的安装和卸载使用跨进程文件锁，防止两个管理器实例同时修改它。

旧版本生成的恢复记录没有 SHA-256，无法可靠证明当前文件属于哪一次安装。新版本可以读取它们，但不会自动覆盖/删除无法验证的文件，也不会把当前文件偷偷当作原始备份。需要保留旧记录和备份，先用创建该记录的版本处理或人工核对；本次没有提供自动迁移功能。

## 验证与边界

回归脚本使用临时文件和构造的 PE 文件，无需显卡、游戏或运行时模型。覆盖导入表、延迟导入表、多 API、错误架构、损坏文件、备份损坏、外部修改、配置保留、失败修复、外部安装器失败、路径与锁、旧记录，以及公共卸载接口。GitHub Actions 同时配置 Windows 和 Linux 的 Debug 编译与回归测试。

日志中的文件加载、面板启动或帧传输不能单独证明神经渲染生效。报告只在看到 033 的具体阶段成功记录时给出相应观察，并明确是日志中的历史证据，不是实时帧率或游戏兼容性验收。

本次不提供新的模型/注入器二进制、不实现反作弊绕过、不修改 033 全局设置、不宣称新增硬件支持或实际帧率提升。仓库缺少 `mod files`，Windows 实机启动、ReShade 外部安装器和各路线的实际游戏效果仍需配套运行时验证。外部 ReShade 安装器可能操作系统级 Vulkan 层；本次文件快照只覆盖已知游戏目录文件，不代表能撤销其所有系统变更。

本实现处理可捕获的安装失败；不是断电/进程被强制结束后的完整事务恢复系统。切换路线也不是一个不可分割的事务：如果旧路线卸载成功而新路线发生意外失败，会明确提示当前状态，不会假报切换成功。

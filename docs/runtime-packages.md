# 运行包、适配建议与安装预览

本功能接入用户提供的 033 V6.0.2 包中的 `033-package.json` 思路，在原有 F# / Avalonia 项目中实现独立的声明式安装流程。代码保存在 fork 开发分支，不合并 main。仓库不分发压缩包中的二进制。

## 使用流程

1. 打开游戏的管理窗口，点击「导入 ZIP」。支持根目录或一层/多层目录下唯一的 schema 1 `033-managed-package` 清单。
2. 导入过程核对必需文件、SHA-256 和声明的 PE 位数，保留随包 notices。失败显示缺失/损坏原因，不激活半导入版本。不导入或执行 PowerShell、CMD 安装脚本。
3. 在「运行包版本」选择已导入版本。「分析适配」读取游戏 PE 图形导入、位数、原生 DLSS 文件、引擎标记和已导入的游戏规则，列出候选路线。多 API 会提示确认游戏的启动模式；无 API 证据时阻止安装。
4. 手动选择路线后点「预览所选路线」。逐项列出新增、替换并备份、保留已有 seed 配置、相同文件跳过，以及写入量、原件备份量、备份位置、冲突和未实现的条件。预览不修改游戏文件。
5. 阅读预览并点击「确认按预览安装」。确认时重新生成计划；目标文件、游戏 EXE、包内容或适配证据改变后必须重新预览。执行中继续校验，失败尝试回到安装前状态。
6. 更换或降级已经安装的版本：先用「移除 DLSS」还原当前安装，再从版本列表选择旧包，重新分析、预览、确认。选择下拉框不会直接更改游戏。旧版本保留，可随时重新选择；首版不做跨版本原子切换或自动清理版本。

## 与原有路线的关系

- 「使用导入的运行包」开启时采用本功能的清单路线；关闭时仍使用原项目的 `mod files` 路线。逐文件预览目前覆盖导入包路线，原有外部 ReShade 安装器未纳入这一声明式预览。
- 两套 payload 不会混装。已有管理器安装时，新的运行包预览要求先还原；恢复记录绑定游戏 EXE。
- 包内 `replace` 项在覆盖前备份；已有 `seed` 配置及内容相同的文件跳过，不取得这些文件的所有权。卸载只还原本次实际写入的文件，保留玩家修改的配置与外部文件。
- 记录沿用原恢复格式：`Mode=package:<profile-id>`，`Api=<完整清单 SHA-256>`。不用源包也能卸载，因为恢复依赖原件备份。文件已部署仅表示磁盘状态，不代表神经渲染已生效。

## 接入边界

- 随包说明注明 Vulkan 不支持、纯 DX10/11 原生 DLSS 路径不能作为有效神经渲染路线；适配检查阻止这些情况。RE 和燕云路线要求相应引擎标记/EXE 名。检测到反作弊规则或目录标记时暂停自动部署。
- `MirrorDirectories` 只在对应目录已存在时镜像 `033-runtime/` 文件，覆盖 RE 的 `_storage_` 布局；不会创建一个本来不存在的引擎镜像目录。
- 带 `Component` 的可选多帧转接件被导入和校验，但首版不部署，预览说明原因。显卡代数、帧生成模块和系统依赖的完整判断尚未接入。
- 首版不应用压缩包中的逐游戏挂载点替换、特殊安装子目录、全局驱动/共享 FG 设置、历史 033 安装账本迁移。现存挂载 DLL 内容不同会阻止部署。目录里已有 seed 配置时，需要人工检查它是否能加载新组件。
- SHA-256 验证的是「内容与清单一致」，不是发布者签名或官方认证。
- 包以完整清单哈希作为目录 ID，保存在 `%LOCALAPPDATA%/DLSS5Manager/RuntimePackages`，版本名不用于构造目录。同一清单重复导入会验证已有版本；内容不同的清单即使版本文字相同也分开保存。
- ZIP 限制为 10,000 条目、单文件 1 GiB、总展开 4 GiB、清单 2 MiB。拒绝路径穿越、Windows 设备名/ADS、大小写重复条目、链接、越界与目标 EXE 替换。完整导入后通过同卷目录移动激活版本。
- 磁盘预检考虑写入、原件备份、操作快照和同目录临时副本；实际 IO 失败仍以运行结果为准。
- 可捕获失败有回滚；断电或进程被强制结束的完整恢复事务仍属于后续阶段。
